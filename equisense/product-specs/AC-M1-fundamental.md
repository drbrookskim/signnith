# AC-M1 — Module 1: 펀더멘털 엔진 수용 기준

> 각 AC 항목은 PR 머지 전에 검토자가 직접 확인해야 합니다.
> ✅는 자동 테스트로 검증 가능, 👁️는 수동 확인이 필요한 항목입니다.

---

## AC-M1-001: 재무제표 API 엔드포인트 ✅

`GET /companies/{ticker}/fundamentals?market={KR|US}` 엔드포인트가 존재하고, 올바른 ticker와 market 파라미터를 전달하면 200 OK와 함께 손익계산서, 대차대조표, 현금흐름표 최근 5개 연도의 데이터를 JSON으로 반환해야 합니다. 잘못된 ticker 형식(예: 한국 종목코드가 6자리 숫자가 아닌 경우)에는 400 Bad Request를 반환해야 합니다.

## AC-M1-002: 캐싱 동작 검증 ✅

동일한 ticker에 대해 두 번째 요청이 들어왔을 때, Lambda 함수 내에서 외부 API(FMP/Alpha Vantage) 호출이 발생하지 않고 Upstash Redis에서 응답이 반환되어야 합니다. 이는 로그에서 확인합니다. Redis TTL은 재무제표 기준 86,400초(24시간)이어야 합니다.

## AC-M1-003: 핵심 지표 계산 정확도 ✅

API 응답에 다음 지표가 포함되고 계산이 정확해야 합니다. ROE는 (당기순이익 / 자기자본) × 100으로 계산되어야 하며, 부채비율은 (총부채 / 자기자본) × 100, 영업이익률은 (영업이익 / 매출액) × 100으로 계산되어야 합니다. 정확도 검증은 FMP 공식 문서의 샘플 데이터와 비교합니다.

## AC-M1-004: 프론트엔드 차트 렌더링 👁️

재무제표 페이지에서 매출액, 영업이익, 순이익의 5개년 추이가 막대 차트로 시각화되어야 합니다. 차트는 모바일(375px), 태블릿(768px), 데스크톱(1280px) 해상도에서 모두 정상 렌더링되어야 합니다.

## AC-M1-005: 오류 처리 ✅

외부 API가 응답하지 않거나 Rate Limit에 도달한 경우, Lambda 함수는 지수 백오프(1초, 2초, 4초)로 최대 3회 재시도 후 503 Service Unavailable을 반환해야 합니다. 클라이언트에는 API 키나 내부 오류 메시지가 노출되어서는 안 됩니다.
