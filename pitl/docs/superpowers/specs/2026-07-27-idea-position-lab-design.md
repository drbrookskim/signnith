# idea-position-lab 설계 스펙

## 목적

상품기획 진단 도구. 기존 마케팅 분석/전략 프레임워크(3C, SWOT, STP, Five Forces, VRIO, Kano, 포지셔닝맵, 4P, Ansoff, 블루오션 전략캔버스, 린 캔버스, BMC, AARRR)를 활용해 아이디어의 현재 "위치"를 진단하고(분석군), 다음 단계로 나아갈 1차 전략을 제시한다(전략군). 주식 기술적 분석처럼 규칙 기반으로 위치를 판정하고 정형 전략 문구를 매칭하는 재계산 도구(Lab Template)와, 클로드가 그 위에서 서술형으로 작성하는 리포트(Lab Report) 두 산출물로 구성된다. (2026-07-30 갱신: 초기엔 "AI 없이도 재사용 가능"을 목표로 뒀으나 이후 Diagnosis/Lab Report 등 클로드의 판단이 필요한 기능이 핵심으로 추가되며 폐기됨 — SKILL.md가 최신 원칙을 따른다.)

## 기존 하네스와의 관계

PITL 하네스(3c-analysis → 4p-strategy → idea-to-strategy, 프로토타입까지)와 완전 독립. 이름 겹침 방지 위해 3C/4P 프레임워크는 이 안에서도 다루되 별도 구현.

## 구성 요소

### 1. `.claude/skills/idea-position-lab/SKILL.md`
스킬 정의. 트리거 예: "위치 진단해줘", "포지션 분석기 만들어줘", "idea position lab". 실행 시 `references/methodology.md` 규칙을 기반으로 자기완결형 HTML 아티팩트를 생성/갱신한다. 스킬은 아티팩트를 최초 생성(또는 규칙 변경 시 재생성)할 때만 필요하며, 이후 사용자는 아티팩트만으로 반복 사용 가능.

### 2. `.claude/skills/idea-position-lab/references/methodology.md`
규칙북(단일 진실 원천). 13개 프레임워크를 분석군/전략군으로 분류하고 각각에 대해 정의한다:
- 입력 스키마 (체크박스 옵션 목록 + 한줄 텍스트 필드)
- 판정 로직 (매트릭스형: 사분면 규칙 / 점수형: 구간 경계값 / 캔버스형: 로직 없이 요약만 / 조건분기형: 상위 분석 결과 참조 규칙)
- 위치→전략 캔드 텍스트 매핑표 (조건 → 고정 문구, 문구 자체는 이 문서에 실제 워딩으로 채워짐)

공통 입력(아이디어 한줄설명, 타겟고객 한줄, 주요경쟁사 한줄, 시장성장세 체크)은 최초 1회만 입력받아 여러 프레임워크가 재사용한다.

### 3. Artifact (자기완결형 HTML/JS)
실제 산출물. 구조:
- 공통 입력 섹션 (1회)
- 분석군 섹션 7개: 3C, SWOT, STP, Five Forces, VRIO, Kano, 포지셔닝맵 — 프레임워크 성격에 맞춰 매트릭스 좌표 / 라이프사이클 단계뱃지 / 점수카드 중 선택적으로 표현
- 전략군 섹션 6개: 4P, Ansoff, 블루오션 전략캔버스, 린 캔버스, BMC, AARRR — 분석군 결과를 조건으로 받아 캔드 전략 문구 노출
- 클라이언트 JS 규칙엔진: 체크박스/텍스트 입력 → 즉시 계산 → 결과 표시. 서버·API 호출 없음.
- "마크다운으로 내보내기" 버튼: 현재 입력값+계산결과를 `.md` 파일로 클라이언트에서 다운로드 (Blob/download 속성 사용, 외부 호출 없음)

## 데이터 흐름

```
스킬 실행(1회, methodology.md 참조)
  → HTML 아티팩트 생성/발행
  → 사용자가 브라우저에서 공통입력 + 프레임워크별 체크박스/한줄입력 채움
  → JS 규칙엔진이 즉시 위치 판정 + 캔드 전략문구 표시
  → (선택) "내보내기" 클릭 → 마크다운 리포트 다운로드
```

이후 프레임워크 규칙 자체를 바꾸지 않는 한 스킬(=Claude) 재호출 불필요.

## 범위 밖 (YAGNI)

- 사용자 계정/저장 기능 (매번 새로 입력하거나 브라우저 로컬스토리지 정도만, 서버 저장 없음)
- 프레임워크 문구의 다국어화
- 프레임워크 커스터마이징 UI (프레임워크 추가/삭제는 methodology.md 직접 수정으로 처리)
- 기존 PITL 하네스와의 데이터 연동
